# FILMCRAFT — the craft I skipped (script · storyboard · grammar · choreography)

Studied 2026-06-26 via a verified multi-source research pass (deep-research, 24/25 claims
confirmed 3-0, 1 refuted). This file exists because I shipped an Agora "promo" that was
**aesthetic slides under a voiceover** — fluff, no meat, lazy transitions, zero shot
choreography, and no script/storyboard discipline. The point of video is *meaning*, not motion.
Read this BEFORE ESSENCE's promo template; the template is the skeleton, this is the craft.

> Sourcing note: editing-grammar + cinematography + montage + Murch are primary-text canon
> (Murch *In the Blink of an Eye*; Eisenstein *Film Form*; Bordwell & Thompson *Film Art*;
> Mascelli *Five C's*; Balázs). The short-form second-budgets (Hook 1-3s / CTA 3-7s) are
> marketing heuristics, not laws. Transition *semantics* (J/L-cut, match, smash, dissolve) are
> established convention but were NOT independently verified this run — use, but don't cite as gospel.

## 1. SCRIPT THE MEAT FIRST (substance > fluff)

**The single highest-leverage move: replace every vague abstract claim with a concrete,
sensory-specific scenario.** That is "show, don't tell" in copy form, and it is what separates
meat from fluff.
- Fluff: *"Communication challenges plague modern businesses."* / *"Big-team output, small-team budget."*
- Meat: *"It's 3 PM. Half your team still hasn't seen the update buried in their inbox."*
- **Put the proof IN the cut, never in the VO alone.** A benefit asserted in narration is fluff;
  the same benefit *shown* — a number on screen, a live demo moment, a before/after — is meat.
- **Narrate OUTCOMES, not actions.** "Click the reports tab" explains the product; "and now
  everyone sees the same number" sells the result. Show ONE workflow end-to-end (a single real
  use case), not a feature list. (whatastory demo-script discipline.)
- **Feature vs demonstrated proof:** "every skill is gated" is a feature claim. *Showing* an
  agent get refused a command it lacks permission for is proof. Always reach for the proof.

**Pick a beat-frame before writing** (don't free-associate):
| Frame | Beats | Best for |
|---|---|---|
| **Pixar story spine** | Once upon a time / Every day / **Until one day** (= inciting incident) / Because of this ×2 / Until finally / Ever since | narrative pitch with stakes |
| **PAS** | Problem → Agitate (consequences of inaction) → Solution | pain-driven demo |
| **PASTOR** | Problem · Amplify · Story · Transformation · Offer · Response | 60-90s complex/SaaS offer |
| **AIDA** | Attention · Interest · Desire · Action | product launch / sales |
| **Hook-Value-CTA** | Hook (1-3s) · Value (mid) · CTA (3-7s) | short-form time budget overlay |
The "Until one day" / Agitate beat is the engine — it converts a static status quo into a story
with momentum. My Agora cut had no inciting moment; it just listed.

## 2. EDITING GRAMMAR — cut for meaning, not on the beat

**Walter Murch's Rule of Six** (priority order; when forced to compromise, sacrifice from the
BOTTOM up — never give up emotion to keep spatial continuity):
1. **Emotion — 51%** (does the cut serve what the viewer should *feel*?)
2. **Story — 23%** (does it advance the argument?)
3. **Rhythm — 10%** (is it the right moment?)
4. **Eye-trace — 7%** (does the eye land where the next shot needs it?)
5. **2D plane / 180° continuity — 5%**
6. **3D spatial continuity — 4%**
→ Emotion outweighs the bottom five combined. **Cut for the persuasive/emotional beat first.**

**Blink theory:** a blink marks the end of a thought. Place cuts on thought-completion
boundaries; control rhythm with **shot length** (short = tension/energy, long = weight/dwell).
**REFUTED this run:** "shorter shots / faster cutting is always more engaging" (0-3). Faster ≠
better — my Agora promo cut every ~3.5s uniformly on the music with no emotional ranking. Wrong.

**Eisenstein — montage is COLLISION, not succession.** Meaning arises from *juxtaposing two
shots* so the viewer synthesizes a third idea: problem-shot ✕ solution-shot, before ✕ after,
manual-pain ✕ one-click. I concatenated 12 slides in a row and collided nothing.

**Transition vocabulary — each one MEANS something** (convention, not verified-canon):
| Transition | Signifies | Use when |
|---|---|---|
| **Hard cut** | continuity / same beat | default; momentum within a thought |
| **Match cut** | conceptual link between two states | morph problem→solution, old way→new way |
| **J-cut** (audio leads) | pull viewer forward into next shot | smooth VO/scene hand-off |
| **L-cut** (audio lingers) | reaction / emotional carry-over | hold a feeling across a visual change |
| **Smash cut** | jolt / hard contrast | the "agitate" hit, a punchline |
| **Dissolve** | time passing / soft section break | montage of progress, "later…" |
| **Fade** | full start/stop, chapter | open, close, major section |
My promo used exactly ONE transition (hard cut on the beat) plus a default xfade. Lazy.

## 3. SHOT CHOREOGRAPHY — build scenes, don't slap full-frame stills

**Shot-size ladder** (each size has a job): Establishing/ELS → LS → Full → Medium → MCU → **CU →
ECU**. The grammar of a scene is **establish → detail**: a wide to ORIENT (where are we), then
push to a **CU on the payoff** (the metric, the UI element, the face). A CU fosters subjective
identification; an ECU isolates the one thing that matters. I shot everything at one size
(full-frame slide / full screen-capture) — no ladder, so no emphasis.

**Camera movement = meaning:**
- **Push-in (dolly in)** → intimacy / tension / reveal of internal state. The move for the "aha".
- **Pull-out** → isolation / context / scope reveal (loneliness, or "look how big this is").
- Pan / whip-pan / crane / handheld each carry energy; pick on purpose. Ken Burns on a slide is
  not choreography — it's wallpaper motion with no narrative intent.

**Angle encodes power:** low angle = dominance/empowered, high angle = vulnerability/diminished,
**eye-level = equality/trust**. Frame the *user* as empowered, the product at eye-level for trust.

**Composition / blocking:** arrange multi-element frames in a **triangle** to lead the eye and
show relationships. **Mise-en-scène** = everything in frame is a choice.
**Miyazaki's "Ma"** — deliberate empty pauses between actions — give a beat room to land; not
every second must be packed. (My promo had zero breathing room; wall-to-wall VO.)

**Choreograph energy across the whole sequence** — a rising-then-resolving intensity curve, not
12 equal beats. Name the 1-2 beats the video is FOR and give them the emphasis (push-in + CU +
a held moment); compress the connective tissue.

## 4. THE PIPELINE — anime/film plan EVERY shot before they draw one

The discipline I skipped entirely. Order is **strict and sequential**:

**脚本 (script) → 絵コンテ (ekonte / storyboard) → レイアウト (layout) → 原画 (key animation).**

The **演出 (episode director)** personally draws the ekonte — it's the single document carrying
the director's intent to the whole team. It **subdivides the episode into numbered cuts**, and
**each cut is timed (seconds + frames/コマ) so the total fits the runtime** — cut numbers persist
through the entire production (~300 cuts/episode). Film does the same with **script → storyboard
→ shot list → script lining**. Miyazaki even boards before a full script ("you start to draw;
the story will follow"). Pixar boards every beat before animation.

**The ekonte panel = my missing shot-list template.** Each panel/row specifies, per cut:
`cut # | thumbnail/framing | action + camera move | dialogue/VO | SFX | timing (sec+frames)`.
**This IS the EDL I should author before touching `sequence.py`.** Budget the durations to sum to
60-120s up front, instead of letting VO length accidentally decide everything (what I did).

## 5. THE METHOD (do this, in this order, every time)

1. **SCRIPT (meat):** pick a beat-frame (§1). Write each line as a *demonstrated proof* (number /
   before-after / live moment), swapping every abstract claim for a concrete scenario. Find the
   inciting beat. Decide the ONE end-to-end workflow you'll show.
2. **STORYBOARD (ekonte):** one numbered row per cut — framing (shot size) · camera move ·
   duration(s) · VO · on-screen text · SFX · **transition-in (and why)**. Sum to target runtime.
   *Confirm this shot-list with the user BEFORE rendering.*
3. **CHOREOGRAPH:** per cut, establish→detail; push-in on the aha, pull-out for scope; angle for
   power/trust; triangle compositions; a rising→resolving energy curve; "Ma" pauses on key beats.
4. **EDIT (Rule of Six):** cut for emotion first; cuts on thought/blink boundaries; rhythm via
   shot length (not uniform); build at least one **montage collision** (before✕after / problem✕fix).
5. **TRANSITIONS on purpose (§2 table):** vary them and make each mean something. Never one-default.
6. **PROOF-IN-THE-CUT audit:** for every benefit, is it SHOWN (metric/demo/before-after) or merely
   ASSERTED in VO? Convert assertions to demonstrations or cut them.

## 6. Post-mortem — my Agora promo graded against the above (so I don't repeat it)

| Failure | Principle violated |
|---|---|
| VO asserted "small team, big output" — no number, no demo, no before/after | §1 proof-in-the-cut; §2 Eisenstein collision unused |
| 12 roughly-equal beats cut uniformly on the music | Murch (cut for emotion, not the beat); refuted "faster=better"; §3 energy curve |
| Every shot full-frame (slide or whole screen capture), one size | §3 shot-size ladder, establish→detail |
| Ken Burns as the only "motion" | §3 movement-as-meaning (no push-in on any aha) |
| One transition type (hard cut + default xfade) | §2 transition vocabulary |
| Jumped straight to `sequence.json` assembly | §4 no script-frame, no numbered ekonte shot-list, no runtime budget |
| No breathing room, wall-to-wall VO | §3 "Ma" |
| Listed features, never showed ONE workflow end-to-end | §1 narrate outcomes, single use case |

**Open / unproven:** transition semantics weren't independently verified this run (re-check vs a
primary editing text). And there's no A/B evidence here that film-craft beats slides-on-VO for
*conversion* — the case is craft authority, not measured lift. Worth testing on a real cut later.

## §7 — Lessons from the Agora pitch redo (2026-06-28)
The first cut was rejected as "dead." Four root causes, each now a rule:

1. **Build an object-level source map BEFORE storyboarding.** Watch every source and write it down
   as an *object*: what it is, the elements inside it, where the beats fall, palette/motion, the
   **persistent anchors it shares with other clips**, and its in/out transition affordances. Without
   this there's no material for content-motivated transitions and the story has nothing to stand on
   → it feels dead. Pattern artifact: `decks/agora/SOURCE-MAP.md`. This is **step 0**, not optional.
2. **Transitions must be motivated by shared elements, not defaults.** A real match-cut is a HARD
   cut on matched composition (e.g. avatar-on-platform → avatar-on-ring), not a crossfade. Other
   knowledge-driven moves: rail-anchored panel swap (a shared static UI element = "one environment"),
   element-carry (an agent's name persists ONLINE→roles), text-build (let on-screen text change BE
   the transition). Derive them from the source map's "shared anchors".
3. **Tone matches the SUBJECT — don't default to dark cinematic.** Vignette + cold grade + black
   doom-cards + white strobe flashes read as *horror*; wrong key for a collaborative/creative tool.
   Wear the product's own palette (Agora = living violet/pink/cyan neon → `grade:"neon"`, no vignette,
   deep-indigo cards, violet glow flashes, synthwave). Ask "what does this product *feel* like?" first.
4. **Pacing: features own the runtime.** Compress problem + onboarding hard; give the actual features
   full, fuller-played screen time (the meat is the demo, not the setup).
